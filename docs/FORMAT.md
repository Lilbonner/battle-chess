# Battle Chess (Mac B&W 1.0.2): форматы данных и устройство движка

Заметки по результатам разбора оригинальной игры, на которых построен режим «Battle Chess» в этом порте.
Здесь только описания форматов и алгоритмов — никаких данных самой игры.

## Файлы диска
- Том HFS (`BattleChess_1_0_2.dsk`): `Battle Chess` (приложение), `ALLCANM1`, `ALLCANM2` (данные анимаций).
- Ресурсы приложения: `CODE` (68k-код, сегменты с 4-байтовым заголовком), `DATA`/`ZERO`/`DREL` (инициализированные
  глобальные переменные Aztec C, адресуются от A5), `PICT 400..403` — картинки фигур для диалога превращения пешки,
  `MENU`, `DLOG`/`DITL`, `ICN#`.
- Имена функций восстанавливаются по символам MacsBug в конце каждой функции.

## Ключевые функции
- CODE 14: `SETUPSEF`, `SETUPSEQ`, `LOADMOVE`, `LOADSFX`, `PLACE`, `WAITANIM`, `STARTANIM`, `ACTIVATE`,
  `HANDLEALL`, `HANDLEWALK`, `HANDLEHWALK`, `HANDLESLIDE`, `HANDLECP`, `HANDLETR`, `HANDLETU`, `HANDLEST`,
  `HANDLECOMBAT`, `CHECKTIME`, `PAWNPROMOTE`, `PUTPIECE`.
- CODE 7: `MAKESHAPE` (копия ключевого кадра или XOR дельты на предыдущий), `RENDERSHAPE`, `DOWALK` (постановка хода и взятия).
- CODE 5: декодер Хаффмана. CODE 10: `PLAYSFX`.

## Сжатие
Поток Хаффмана: `[u32 размер][u32 ?]`, затем битовый поток MSB-first 16-битными словами: сериализованное дерево
(бит 1 — лист и 8-битный символ; бит 0 — левое поддерево, один пропускаемый бит, правое поддерево), затем коды.

## Спрайты
- 2 бита на пиксель, `(w+3)>>2` байт на строку: 0 — контур, 1 — блик, 2 — тело (цвет стороны), 3 — прозрачность.
- Запись кадра `(w, h, hx, hy)`, hx/hy — знаковые байты точки привязки; спрайт рисуется в `(x-hx, y-hy)`.
- Блок SEF: список записей u32 + поток Хаффмана со всеми полными кадрами.
- Блок SEQ: 6-байтовые записи `(w, h, hx, hy, u16 длина в битах)`, нулевая запись, затем последовательности
  `[len][key][len индексов кадров]` и поток. Кадры последовательности — XOR-дельты к предыдущему кадру.
  `key`: бит 7 — ключевой кадр берётся из стоячих поз (`key & 0x7f`), иначе — из боевого SEF своей стороны.
- Стоячие позы 0..46: слон 0–3 (4 диагонали), король 4–11 (8 направлений), конь 12–15 (N, E, S, W),
  пешка 16–23 и 39–46, ферзь 24–31, ладья-голем 32–35, ладья-башня 36–38. Направления — по часовой стрелке от N (от зрителя).

## Ход фигуры
- Движок шагает раз в 6 тиков Mac — 10 кадров в секунду.
- Экранные координаты клеток: x — таблица из 64 слов, y — из 8 слов (ряд 0 — дальний).
- Активности: WALK, TURN, ST, HWALK, COMBAT, TR (превращение ладьи), CP (выход на позицию боя), SLIDE.
- Поворот — кратчайшим путём (при равенстве — против часовой), последовательностями поворота
  (`8+f` по часовой, `16+f` против для фигур с 8 направлениями; `4+f/2` и `8+f/2` — для 4 направлений).
- Ходьба: цикл ходьбы проигрывается ровно один раз на клетку, позиция интерполируется по кадрам.
- Ладья: последовательности 14/15 — башня→голем (N/S), 16/17 — голем→башня.
- Конь идёт буквой «Г»; фигура на пути отступает на `DX/DY = [0,19,19,19,0,-19,-19,-19] / [-9,-9,0,9,9,9,0,-9]` пикселей.

## Взятие (DOWALK)
- Победитель идёт к жертве; при движении на S, SW или W он останавливается на клетку раньше.
- Жертва поворачивается на SW (конь — S, ладья становится големом лицом на S), полушагом отходит на (−25, +13) пикселей
  от центра клетки и поворачивается на NE (ладья и конь — на N). Если победитель идёт на NE, жертва сначала делает полушаг на W.
- Победитель входит на клетку, поворачивается на NE (ладья, конь — N), выходит на (+15, −1) — полным циклом,
  если остановился раньше, иначе полуциклом, — и поворачивается на SW (S).
- После сцены победитель полуциклом возвращается в центр клетки и поворачивается «домой»; ладья снова становится башней.

## Сцена поединка
- Боевые блоки выбираются по типам фигур; каждая сторона — блок SEQ и следующий за ним SEF.
- Таблицы пар (заполняются при запуске из DATA): T01 — плейлист последовательностей стороны,
  T23 — сценарий тайминга и звука: байты > 0x7f (кроме 0xff) — звук `[0x80|sfx, высота+0x40]`, остальные — задержка в тактах, 0xff — конец.
- `CHECKTIME` каждый такт: пока задержка > 0 — уменьшить и ждать; иначе сыграть звуки, прочитать следующую задержку
  и показать следующий кадр (`HANDLECOMBAT`).
- Обе стороны привязаны к клетке взятия; побеждённый рисуется на пиксель ниже, то есть впереди.
